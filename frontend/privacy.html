Pilot Privacy Notice

This notice describes what RealityCheck AI collects, processes, stores, and deletes in the current software. It is a pilot disclosure for invited users. It is not a certification of legal compliance, including under Indian privacy law. Provider retention periods and legal guarantees are not invented here.

1. Who we are

RealityCheck AI is an evidence-investigation tool. It helps you search for sources, compare them with a claim you submit, and optionally examine an uploaded image’s file identity and Content Credentials status. It does not guarantee that a claim or image is true.

2. Information collected

Account and authentication

  • Email address
  • Password stored only as an Argon2id hash (not the password itself)
  • Session cookie token hash and CSRF token

Investigations

  • Submitted claims or pasted URL-related text
  • Extracted claims and search queries
  • Retrieved source URLs, titles, snippets, quality and timeline fields
  • Fetched page text when you request a page extract

Images

  • Original uploaded image bytes for supported formats: JPEG, PNG, GIF, and WebP
  • Server SHA-256 hash, byte length, media type, and upload consent version

Image metadata (separate consent)

  • If you accept metadata consent, selected embedded fields such as camera, date, and location may be extracted
  • Precise GPS may be retained in protected sealed records when present in the file

Technical and security records

  • Rate-limit counters (visitor address for login and registration; account id for investigation actions)
  • Sealed assessment snapshots and Content Credentials status records

3. Image upload and metadata consent

These are separate decisions.

  1. Image upload consent — Required before the original file is sent to the RealityCheck AI server. The original bytes are stored until your account is deleted (or the image is removed in a deletion flow). Declining metadata consent does not remove embedded EXIF from the uploaded original file; those bytes may already contain GPS or camera details.
  2. Metadata extraction consent — Optional. Only if you accept does the server read allowlisted camera, date, and location fields for sealed records.

The server calculates a SHA-256 of the received bytes. That hash identifies the file. It does not prove authenticity or that the pictured event happened.

Public assessment responses do not expose precise GPS. Precise coordinates, when retained, are available only through an authenticated reveal for that snapshot. A backup made before deletion can still contain the file and those fields.

4. Third-party providers

Some processing is performed by external services. RealityCheck AI does not control their retention policies.

Parallel

Used for search and webpage extraction. The application may send short search queries and page URLs. Retrieved titles, snippets, and page text may be stored in your investigation.

OpenAI

Used for claim extraction and assessment. The application may send submitted claim or page text (capped for extraction), verifiable points, and a catalogue of stored sources (host, quality, date, title, snippet), plus whether an image was sealed. Image bytes, GPS, camera details, and file hashes are not included in the assessment prompt.

Passwords and session cookies are not sent to these providers. Copies may remain on provider systems under their own terms — retention periods are unknown to this application and are not stated here as guarantees.

5. Storage and retention

Account and investigation data are stored in the application’s database. Image files are stored beside that database. Investigations are kept until you delete them or delete your account. The application does not currently enforce an automatic investigation expiry period.

Operators may keep backups. Recommended operator practice is multiple daily and weekly copies. The application does not automatically delete backups. Restoring a backup taken before account deletion can restore that account’s data.

6. Account deletion

When account deletion succeeds, the application removes that account’s assessment snapshots, image asset records, cleanup records, evidence sources, page fetches, claim analyses, investigations, sessions, account-scoped rate-limit rows, and the user row, and clears the session cookie. Image files are removed when possible before the database step.

Deletion does not guarantee removal of:

  • Operator backups created earlier
  • Third-party provider copies
  • Login or registration rate-limit rows keyed by visitor address
  • All physical remnants on disk until operators rotate or overwrite storage

If an image file cannot be removed, the account may remain so deletion can be retried safely.

7. AI assessment limitations

Automated assessments are not conclusive proof of truth. They depend on available evidence and source coverage. Insufficient evidence and unresolved outcomes are valid. Always review cited sources.

8. Content Credentials (C2PA) — pilot Choice A

For this controlled pilot, trusted C2PA credential verification is not production-ready. Content Credentials may show technical or unavailable status. Do not treat those results as trusted verification. File identity and Content Credentials do not establish that a depicted event actually happened. Provenance remains separate from the six claim-assessment outcomes.

9. Security and operational disclosures

Production deployments are expected to use HTTPS, secure session cookies, CSRF protection on state-changing requests, Argon2id password hashing, and restricted database and asset file permissions. Rate limits apply. Residual risks include third-party processing and limits of server-side URL checks when an external search provider opens its own network connection.

This notice does not publish internal secrets, trust material, or server paths.
